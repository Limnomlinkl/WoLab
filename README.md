# WoLab — Wake on LAN для Android

Приложение для удалённого включения ПК по технологии **Wake on LAN**: отправляет
magic packet в локальную сеть и проверяет, что компьютер действительно запустился.

## Возможности

- **Профили сетей и устройств** — несколько сетей, в каждой свой список устройств
  (имя, IP-адрес, MAC, порт проверки доступности).
- **Отправка magic packet** — UDP на порт 9, пакет дублируется 5 раз с интервалом
  200 мс; используется направленный broadcast подсети, а при неудаче — `255.255.255.255`.
- **Проверка запуска** — после отправки пакета приложение в течение 30 секунд
  опрашивает TCP-порт устройства (по умолчанию 3389) и показывает статус:
  отправка → ПК запускается → запустился / не удалось запустить.
- **Локальное хранение** — данные в Room, никакой отправки на сторонние серверы.
- **Локализация** — русский и английский языки, тёмная и светлая темы.
- **Архитектура** — MVVM, LiveData, Navigation, Hilt (DI), ViewBinding.

## Навигация

На главном экране две карточки — **Сеть** и **Устройство**. Нажатие на карточку
открывает соответствующий список:

- карточка «Сеть» → список сетей: добавить, переименовать, удалить, выбрать;
- карточка «Устройство» → список устройств выбранной сети: добавить,
  переименовать, изменить IP, удалить, выбрать.

Пунктов «Изменить сеть / Изменить устройство» в меню «три точки» больше нет —
в меню остался только выход.

## Установка (APK)

Готовые сборки публикуются в разделе
[**Releases**](https://github.com/Limnomlinkl/WoLab/releases).
Скачайте файл `*.apk` из последнего релиза и установите его на устройство
(потребуется разрешить установку из неизвестных источников).

## Сборка из исходников

Требования: JDK 17, Android SDK (compileSdk 36), Gradle 8.13 (wrapper в комплекте).

```bash
# Debug-сборка
./gradlew assembleDebug

# Release-сборка (подписанная — см. раздел «Подпись»)
./gradlew assembleRelease
```

APK появится в `app/build/outputs/apk/<variant>/app-<variant>.apk`.

### Подпись release-сборки

Параметры ключа читаются из файла `keystore.properties` в корне проекта
(он **не** хранится в репозитории):

```properties
storeFile=.signing/wolab-release.jks
storePassword=…
keyAlias=…
keyPassword=…
```

Путь `storeFile` указывается относительно корня проекта. Без этого файла
собирается неподписанный release APK, который нельзя установить на устройство.

## Обновления без потери данных

Данные (сети, устройства и выбранные элементы) сохраняются при обновлении
приложения, потому что:

- `applicationId` не меняется (`com.example.wol`);
- все релизы подписываются **одним и тем же ключом**;
- `versionCode` увеличивается от релиза к релизу;
- база Room имеет версию 1 и не использует `fallbackToDestructiveMigration()`,
  поэтому схема не пересоздаётся. При будущих изменениях схемы нужно
  увеличить `version` и добавить явную `Migration` (схемы экспортируются
  в `app/schemas/`).

Настройки выбранной сети и устройства хранятся в `SharedPreferences` и тоже
переживают обновление.

## Структура проекта

```
app/src/main/java/com/example/wol/
├── data/        # Room (сущности, DAO, база), репозитории
├── di/          # Модули Hilt
├── domain/      # LaunchOrchestrator — сценарий «отправить пакет и дождаться запуска»
├── network/     # WolSender, HostAvailabilityChecker
└── ui/          # Activity, фрагменты, ViewModel, адаптеры
```
